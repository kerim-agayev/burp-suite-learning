Dərs 25. Authentication — Pillə 2: 2FA (iki addımlı giriş) məntiq xətası

bitdi

Giriş nöqtəsi: POST body (form), sonra Cookie ilə müqayisə. Lab: /vuln/2fa · /secure/2fa.

🔧 POST body nədir — sıfırdan

Form göndəriləndə mətn belə görünür: step=verify&username=administrator&code=42. Bu, form-urlencoded body adlanır.

QaydaMisal
ad=dəyər — bir forma xanasıusername=administrator
& — cütləri ayırırstep=verify&username=...&code=...

Adlar (step, username, code) saytın HTML formundan gəlir (<input name="username">). Format ?category=Gifts (URL) ilə eynidir — fərq yalnız yerdir: URL-də görünür, body-də görünmür (yalnız Burp-da).

🧪 Hücum — username sahəsini dəyiş
  1. /vuln/2fa-da wiener/peter ilə login → öz kodumuz (məs. 28) ekranda göründü, forma: "İstifadəçi adı (dəyişə bilərsən!)" + "Kod".
  2. Verify request-ini Repeater-ə göndərdik, body-ni dəyişdik: step=verify&username=administrator&code=28 (öz kodumuz, amma admin adı ilə).
  3. "Kod yanlışdır" gəldi — amma lab-ın öz xətası səhv cəhddə əsl kodu göstərdi: 42. Bunu istifadə edib username=administrator&code=42 göndərdik → admin panelə girdik, parolu heç bilmədən.

Əsas zəiflik: server yoxlamır ki, kod həqiqətən bu adama, bu sessiyaya aiddir — sadəcə "username+code uyğun gəlirmi" sualına baxır. username client-dən (formadan) gəldiyi üçün dəyişdirilə bilir.

🛡️ Qorunma — Cookie ilə sessiya bağlamaq

/secure/2fa-da verify formunda username sahəsi YOXDUR. Əvəzinə:

Anlayışİzah
Cookie: tfa_session=abc123xyzserver-in verdiyi təsadüfi bilet nömrəsi — brauzer hər request-də öz-özünə geri göndərir
Server-in yaddaşıbilet → {username, kod} — bu əlaqə yalnız serverdədir, client görmür/dəyişmir

Login edəndə server bileti verir, kod yoxlananda "bu bileti kim gətirib?" sualı ilə əsl username-i öz yaddaşından tapır. Biletin son hərfini dəyişdirdikdə — "kod yanlışdır, sessiya tapılmadı" (Dərs 15-dəki təsadüfi token = təxmin olunmaz qaydası).

  • Qayda: kimliyi (username) müəyyən edən məlumat client-in yaza bildiyi formadan yox, server-in öz yaddaşından (sessiyadan) gəlməlidir.
