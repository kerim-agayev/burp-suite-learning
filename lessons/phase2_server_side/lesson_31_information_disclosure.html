Dərs 31. Information disclosure — server lazımsız məlumat sızdırır

bitdi

Mərhələ 2, mövzu #6. Giriş nöqtəsi: URL parametri (xətanı yaratmaq üçün) + response header-ləri. Lab: /vuln/account · /secure/account.

🔧 Bənzətmə

Ofisiant sifarişi çatdıra bilməyəndə "üzr istəyirik" deməlidir. O isə mətbəxin resept dəftərini, anbarın şifrəsini və kassa kodunu masaya qoyur. Üstəlik formasının üzərində "mən filan şirkətin işçisiyəm, filan sistemdən istifadə edirəm" yazıb.

🧪 Nə etdik
  1. /vuln/account?id=abc → id ədəd olmalı idi, "abc" göndərdik. Server xətanı JSON-da olduğu kimi qaytardı: DB connection string (istifadəçi adı, şifrə, host), fayl yolu və stack trace göründü.
  2. /secure/account?id=abc → yalnız Invalid request. Detallar server loquna (console.error) yazıldı, client-ə getmədi.
  3. Ana səhifənin response header-lərində X-Powered-By: Next.js tapdıq: server öz texnologiyasını özü deyir (fingerprinting).

Niyə işlədi: inkişafçı xəta ayıklamaq üçün ətraflı mesaj yazır, amma onu client-ə də göndərir. Hücumçu bilərəkdən səhv giriş göndərib xətanı provokasiya edir və daxili quruluşu öyrənir.

Header-lər (qısa xəritə): request header-lərini hücumçu dəyişir (Cookie, Authorization, X-Forwarded-For, Host, User-Agent, Referer/Origin, Content-Type), response header-lərinə baxır (Set-Cookie bayraqları, Server/X-Powered-By, Access-Control-Allow-Origin, CSP, X-Frame-Options, Location, Cache-Control).

🛡️ Qorunma
  • Qayda: xəta detalları yalnız server loquna yazılır, client-ə ümumi mesaj gedir ("Invalid request").
  • Production-da debug rejimi söndürülür, stack trace göstərilmir.
  • Texnologiya/versiya header-ləri gizlədilir (Next.js-də poweredByHeader: false).
  • Şifrə və açarlar heç vaxt koda/mesaja yazılmır, mühit dəyişənlərində saxlanır.
