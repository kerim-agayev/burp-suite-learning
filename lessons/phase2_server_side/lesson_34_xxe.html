Dərs 34. XXE — XML qısaltması vasitəsilə fayl oxutmaq

bitdi

Mərhələ 2, mövzu #10. Giriş nöqtəsi: POST body (XML). Lab: /vuln/greeting · /secure/greeting.

🔧 Bənzətmə

Formada "qısaltma" təyin edirsən: "AZ = Azərbaycan", sonra mətndə "AZ" yazanda sistem onu "Azərbaycan" ilə əvəz edir. XML-də bu ENTITY adlanır. Problem: qısaltmanın mənasını "bu faylı oxu" kimi təyin etmək olar.

🧪 Nə etdik
  1. Normal body: <name>Kerim</name> → {"greeting":"Salam, Kerim"}.
  2. XXE body (Repeater, POST /vuln/greeting, Content-Type: application/xml): 
    <!DOCTYPE foo [ <!ENTITY xxe SYSTEM "file://secret.txt"> ]>
<name>&xxe;</name>
    → server &xxe;-ni secret.txt faylının tam məzmunu ilə əvəz etdi, cavabda (saxta) DB connection string sızdı.
  3. Eyni body /secure/greeting-ə → DOCTYPE/ENTITY olan XML qəbul edilmir, XML-ə baxılmadan rədd edildi.

Niyə işlədi: XML standartı DOCTYPE-də xarici (SYSTEM) mənbədən entity tərifinə icazə verir — bu, bug deyil, standartın bir hissəsidir. Parser susmaya görə bunu həll edə bilir.

Texniki qeyd: real server tətbiqdə bunu adətən inkişaf etmiş XML parser edir; bu lab üçün sadə/minimal entity-həll kodu yazılıb ki, mexanizm aydın görünsün.

🛡️ Qorunma
  • Qayda: parser-də xarici entity-lərin həllini (DTD processing) SÖNDÜR, ya da DOCTYPE/ENTITY olan girişi ümumiyyətlə qəbul etmə.
  • Mümkünsə XML əvəzinə JSON istifadə et — JSON-da entity/DOCTYPE anlayışı yoxdur, bu sinif boşluq mümkün deyil.
