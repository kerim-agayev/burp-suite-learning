Dərs 32. IDOR — başqasının obyektinə id ilə çatmaq

bitdi

Mərhələ 2, mövzu #7. Giriş nöqtələri: URL parametri (?id=) və POST JSON body ({"id":1}). Lab: /vuln/user · /secure/user.

🔧 Bənzətmə

Otel resepsionu açarı sənə verir (kimliyin təsdiqləndi), amma otaq nömrəsini sən deyirsən və o yoxlamır ki, otaq sənindir. 207 desən qonşunun otağına girirsən.

🧪 Nə etdik
  1. wiener kimi (cookie remember=d2llbmVy) /vuln/user açdıq: öz id-miz 2.
  2. /vuln/user?id=1 → administratorun məlumatı (role: admin, balans) göründü.
  3. /secure/user?id=1 → 403 İcazə yoxdur.
  4. Repeater-də GET-i POST-a çevirdik, Content-Type: application/json və body {"id":1} göndərdik: vuln yenə admini qaytardı, secure yenə 403.

Niyə işlədi: server kim olduğunu (authentication) biləndən sonra "bu obyekt bu adama aiddir?" (authorization) yoxlamırdı. id hardan gəlirsə gəlsin (URL, body, cookie, header) nəticə eynidir.

Dərs 27 ilə fərq: orada kimliyi saxtalaşdırırdıq (authentication zəifliyi), burada kimlik düzgündür, amma başqasının məlumatına çatırıq (authorization zəifliyi).

🛡️ Qorunma
  • Qayda: hər sorğuda server tərəfində yoxla: istənilən obyekt (id) girişli istifadəçiyə aiddir, ya da rolu icazə verir. /secure/user-də bu id !== me.id && role !== "admin" yoxlamasıdır.
  • Ardıcıl rəqəm id-lər (1, 2, 3) hücumçuya tapmağı asanlaşdırır (Intruder ilə sıra ilə sınanır); təsadüfi id (UUID) kömək edir, amma əsas qorunma yoxlamadır, gizlətmək yox.
