Dərs 30. Business logic vulnerabilities — server müştəriyə lazımsız güvənir

bitdi

Mərhələ 2, mövzu #5 (Mövzu TAMAM). Giriş nöqtəsi: URL parametri (?price=). Lab: /vuln/checkout · /secure/checkout.

🔧 Bənzətmə

Kassir müştərinin dediyi qiyməti yoxlamadan qəbul edir — "müştəri yalan deməz" deyə düşünür. Bu, SQLi/path traversal kimi simvol oyunu (sintaksis sındırma) deyil, sırf məntiq boşluğudur: heç bir xüsusi simvol lazım deyil, sadəcə dəyəri dəyişirsən.

🧪 Nə etdik
  1. /vuln/checkout?productId=1&price=9999 → normal, bazadakı qiymət göstərildi.
  2. /vuln/checkout?productId=1&price=1 → "Alındı: ... ödənilən: 1" — bazada məhsul 25 AZN olsa belə, server client-in göndərdiyi price-i olduğu kimi qəbul etdi.
  3. /secure/checkout?productId=1&price=1 → "Alındı: ... ödəniləcək (əsl, bazadan): 25" — client-in göndərdiyi price tamamilə nəzərə alınmadı.

Niyə işlədi (vuln tərəf): server ödəniləcək qiyməti sorğudan (searchParams.price) oxuyurdu, bazadan yox. Real tətbiqlərdə eyni səhv POST body-də (price=1) və ya JSON-da ({"price":1}) da baş verə bilər — giriş nöqtəsi dəyişsə də məntiq eynidir: "qiyməti haradan götürürük?"

🛡️ Qorunma
  • Qayda: pul, endirim, rol, balans kimi həssas dəyərlər HEÇ VAXT client-dən gələn dəyərdən (URL/body/cookie/header/JSON — giriş nöqtəsindən asılı olmayaraq) götürülməməlidir. Server HƏR ZAMAN öz bazasından/öz hesablamasından yenidən oxumalıdır.
  • Bu, Dərs 12b-dəki (unsigned rol token) qaydanın eynisidir, sadəcə fərqli sahədə: "client-in dediyinə yox, serverin bildiyinə güvən".
