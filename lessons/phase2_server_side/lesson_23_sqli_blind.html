Dərs 23. Blind SQL injection (SQLi pilləsi 5) — SQLi mövzusu BAĞLANDI

bitdi

Nəticə ekranda görünmür — məlumatı hə/yox suallarıyla, hərf-hərf çıxarmaq. Lab: /vuln/blind, injection cookie-də (URL-dən kənar ilk məşq).

🔧 Blind nədir

Kilidli otağın içini görmürsən, amma qapını döyüb sual verirsən: tıqqıltı (hə) / səssizlik (yox). Lab məlumatı göstərmir, yalnız:

  • Sorğu sətir qaytarır → "Welcome back!" (= HƏ)
  • Qaytarmır → mesaj yoxdur (= YOX)

Giriş nöqtəsi — cookie: server TrackingId cookie-ni oxuyub SQL-ə yapışdırır. Burp Repeater-də Cookie: başlığını dəyişdik (brauzerin URL-inə toxunmadan).

SELECT id FROM "User" WHERE username = '<COOKIE>'
🧪 Addımlar

1) Oracle-ı yoxla (hə/yox düzgün işləyirmi). Diqqət: -- İŞLƏTMƏDİK — serverin sondakı dırnağı bizim stringi bağlayır (dırnaq balansı):

TrackingId=administrator' AND '1'='1   → '1'='1' → DOĞRU → Welcome back
TrackingId=administrator' AND '1'='2   → '1'='2' → YALAN → mesaj yox

Tələ: ...='1-- yazsaq, serverin dırnağı '1--' kimi mətn yaradır, -- şərh olmur. Ona görə burada -- yox, dırnaq balansı işlədirik.

2) Parolu hərf-hərf çıxar — substring(mətn, haradan, neçə) ilə:

TrackingId=administrator' AND substring((SELECT password FROM "User" WHERE username='administrator'),1,1)='s

"1-ci hərf s-dirmi?" → Welcome back = HƏ. 'a' ilə → mesaj yox. Mövqeyi dəyişib (,2,1) 2-ci hərf (3) və s. tapılır.

Blind SQLi = minlərlə hə/yox sualıyla məlumatı hərf-hərf yığmaq. Görünən (UNION) injection-dan yavaş, amma eyni dərəcədə təhlükəli.

🛡️ Qorunma · SQLi mövzusunun yekunu
  • Qorunma (hamısı üçün eynidir): parametrized query / ORM. /secure/blind-də cookie parametr kimi ötürülür → ' AND ... işləmir.
  • SQLi növləri (bitdik): gizli data ('--), login bypass (' OR 1=1--), UNION (başqa cədvəl + recon), blind (hə/yox + vaxt).
  • Vaxt-əsaslı blind (əlavə): cavab fərqi olmasa belə, pg_sleep(5) ilə "doğrudursa 5 saniyə gözlə" deyib cavabın gecikməsindən oxumaq olar.
