Dərs 21. SQL injection — Login bypass (Mərhələ 2 · SQLi pilləsi 2)

bitdi

Parolu bilmədən girmək. Lab: /vuln/login-sql (öz burp-lab saytımız). SQLi A-Z planının 2-ci pilləsi.

🔧 Normal login necə işləyir

Qapıçı bənzətməsi: "Adı X olan VƏ parolu Y olan sətir varmı?" Server bazaya belə sual verir:

SELECT ... FROM "User" WHERE username = 'administrator' AND password = 's3cr3t-Pa55'

Tapılsa → içəri. Problem: ad xanasına nə yazsan, server onu düşünmədən SQL-in içinə yapışdırır.

🧪 Hücum 1 — ' OR 1=1-- (hər kəsi burax)

Serverin şablonu: username = '▢'. İki dırnaq serverindir, sən ortanı doldurursan. ' OR 1=1-- yazanda:

WHERE username = '' OR 1=1--' AND password = '...'
HissəNə edir
' (ilk simvol)serverin dırnağını erkən bağlayır → username = ''
OR 1=1dırnaqdan kənarda = əsl SQL. 1=1 həmişə doğru → "nəsə YA DA doğru" = həmişə doğru
--qalanını (parol yoxlamasını) şərhə salıb silir

Açar fikir: dırnağı erkən bağla → öz SQL-ini əlavə et → qalanını -- ilə sil. Nəticə: bütün sətirlər uyğun, ilk tapılan içəri girir.

🧪 Hücum 2 — administrator'-- (konkret admin)
WHERE username = 'administrator'-- ' AND password = '...'

"adı tam administrator olsun" + -- parol yoxlamasını silir → konkret administrator kimi giriş.

Real həyatda: admin adını bilməyə bilərsən → ümumi adları sına (admin/root), username enumeration (Dərs 11), ya da ' OR 1=1 LIMIT 1-- (birinci istifadəçi). Müasir düzgün saytlar bunu bloklayır (hash + parametrized), amma çoxlu zəif sayt hələ də var.

🛡️ Qorunma — /secure/login-sql

Eyni administrator'-- təhlükəsiz versiyada işləmədi ("giriş uğursuz"). Çünki dəyərlər SQL mətninə yapışdırılmır, parametr kimi ötürülür — administrator'-- bütöv bir ad kimi axtarılır, belə ad yoxdur.

  • Qayda: parametrized query / ORM query builder (Prisma findFirst). Dırnaq mətnin bir hissəsi sayılır, SQL əmri yox.
  • Parolları açıq mətnlə saxlama — hash-la (lab sadəlik üçün açıq saxlayır).

Növbəti pillə: UNION attack (3a: sütun sayı → 3b: mətn sütunu → 3c: başqa cədvəldən parol sızdırmaq).
