Dərs 24. Authentication — Pillə 1: Brute-force lockout bypass

bitdi

Mərhələ 2, Authentication mövzusu başladı. Giriş nöqtəsi: HTTP header (X-Forwarded-For). Lab: /vuln/bruteforce.

🔧 Nə üçün kilid var, necə aldadılır

Bankomatda 3 səhv PIN → kart bloklanır. Server də eyni: N səhv cəhddən sonra "bu IP"-ni kilidləyir. Problem: server IP-ni X-Forwarded-For adlı HTTP başlığından oxuyur — bu, adi mətn sətridir, client özü yaza bilər (Burp Repeater-də əlavə edilir).

🧪 Nə etdik
  1. Brauzerdə /vuln/bruteforce?username=administrator&password=wrong açdıq → "Aşkarlanan IP: 127.0.0.1".
  2. Request-i Repeater-ə göndərdik, Host sətrinin altına əlavə etdik: X-Forwarded-For: 1.2.3.4.
  3. 3 dəfə Send → 3-cü cəhddən sonra "Çox cəhd" mesajı (kilidləndi).
  4. Sadəcə X-Forwarded-For-u 5.5.5.5-ə dəyişdik → kilid sıfırlandı, yenə "parol səhvdir" (yəni sınamağa davam edə bildik).

Nəticə: header-i hər dəfə dəyişməklə sonsuz cəhd mümkündür. Real hücumda bunu Intruder avtomatik edir (hər sorğuda həm parol, həm saxta IP dəyişir).

🛡️ Qorunma — /secure/bruteforce

Eyni hücumu (hər hansı X-Forwarded-For ilə) təhlükəsiz versiyada sınadıq → kilid sökülmədi.

  • Qayda: kilidin açarı client-in göndərə biləcəyi heç nəyə (header, cookie) bağlı olmamalıdır. Bizim fiksimiz: açar = username (hesabın özü) — bunu hücumçu dəyişə bilmir.
  • Real saytlarda server əsl TCP bağlantı IP-sini (proxy-nin özü təyin etdiyi, client-in yaza bilmədiyi) işlədir, ya da CAPTCHA/rate-limit əlavə edir.
  • Ümumi dərs: Dərs 8-dəki qayda təkrarlanır — client-dən gələn heç bir məlumata (header daxil) təhlükəsizlik qərarı üçün güvənmə.
