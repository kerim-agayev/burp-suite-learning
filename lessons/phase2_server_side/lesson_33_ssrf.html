Dərs 33. SSRF — serveri özün əvəzinə hücum etdirmək

bitdi

Mərhələ 2, mövzu #9. Giriş nöqtəsi: URL parametri (?url=). Lab: /vuln/preview · /secure/preview.

🔧 Bənzətmə

Poçtalyona "get bu ünvandan paket gətir" deyirsən. Poçtalyon sənin kim olduğunu soruşmur, hara desən ora gedir — hətta qadağan olunmuş bir binaya da, çünki ONA icazə var, sənə yox.

🧪 Nə etdik
  1. /vuln/preview?url=https://httpbin.org/get → normal, xarici sayt gətirildi.
  2. /vuln/preview?url=http://localhost:3000/vuln/account?id=abc → server özü Dərs 31-dəki zəif endpoint-ə getdi, cavabda yenə DB connection string + şifrə sızdı. Biz birbaşa getməmişik, serverə "get gətir" demişik.
  3. /secure/preview?url=...localhost... → icazə verilməyən host, server heç sorğunu göndərmədi.

Niyə təhlükəlidir: firewall/şəbəkə qaydaları SƏNƏ görə qurulur — bayırdan daxili şəbəkəyə (DB, admin panel, cloud metadata) girə bilmirsən. Server isə artıq həmin şəbəkənin içindədir, ora sərbəst gedir. SSRF-də sən "açarı olan" serverdən "mənim üçün aç bax" xahiş edirsən.

🛡️ Qorunma
  • Qayda: server istifadəçi-verilən ünvana gedəcəksə, hara gedə biləcəyini allowlist ilə məhdudlaşdır (yalnız bəlli xarici domenlər, yalnız https). "Qadağan siyahısı" (localhost, daxili IP-lər) kifayət etmir — fərqli yazılış/yönləndirmə ilə aldadıla bilər.
  • Mümkünsə, server heç bir istifadəçi-verilən URL-ə sorğu göndərməsin; əvəzinə sabit, əvvəlcədən bilinən mənbələrdən istifadə et.
