Dərs 29. Command injection — serverə öz əmrini işlətdirmək

bitdi

Mərhələ 2, mövzu #4. Giriş nöqtəsi: URL parametri. Lab: /vuln/cmdi · /secure/cmdi.

🔧 Bənzətmə

Ofisiantdan "salam de" xahiş edirsən, o mətbəxə yazır. Sən "salam de, SONRA bütün resept kitabını göstər" yazsan, aşpaz hər iki əmri ardıcıl icra edər — sözünü sorğulamadan oxuyur.

🧪 Nə etdik
  1. ?name=dunya → server echo Salam, dunya işlətdi (adi görünüş).
  2. & Windows-da "bu əmri bitir, növbətini icra et" deməkdir. ?name=dunya & whoami yazanda işləmədi — brauzer &-i öz URL-parametr ayırıcısı kimi oxudu, server whoami-ni heç görmədi.
  3. Düzəliş — Dərs 3-dəki encoding: &-i %26 kimi yazdıq: ?name=dunya%20%26%20whoami → bu dəfə işlədi, server-in Windows istifadəçi adı sızdı.

Niyə işlədi: server name dəyərini birbaşa shell əmrinə yapışdırdı (exec("echo Salam, " + name)). Shell &/| kimi işarələri **əmr ayırıcı** kimi oxuyur, mətn kimi yox.

🛡️ Qorunma

/secure/cmdi-də eyni giriş → rədd edildi ("yalnız hərf, rəqəm və boşluğa icazə verilir").

  • Qayda: allowlist — giriş yalnız gözlənilən simvollara (hərf/rəqəm) uyğun gəlirsə qəbul olunur, uyğun gəlməyən hər şey rədd edilir. &, |, ; kimi shell-üçün-xüsusi simvollar heç vaxt keçmir.
  • Ən yaxşı qayda: istifadəçi girişini heç vaxt shell əmrinə ötürmə. Lazımdırsa, shell-siz funksiyalar (execFile array arqumentlə) işlət.
