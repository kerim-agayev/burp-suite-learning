Dərs 15. Sequencer — token təsadüfiliyi

bitdi

Qapı açarı ardıcıl olsa (1001, 1002...) oğru növbətini təxmin edər. Təsadüfi olsa, mümkün deyil. Sequencer bunu ölçür.

🔧 Necə işlədilir

Canlı endpoint lazım deyil — Manual load ilə əldə olan token nümunələrini yükləyib analiz etmək olur. Ən azı 100 token lazımdır (statistik analiz üçün).

Nəticə: Summary tabında "Overall result" — keyfiyyəti sözlə (poor/excellent) və effektiv entropiya-nı bit ilə göstərir. Nə qədər çox bit, bir o qədər təsadüfi/təhlükəsiz.

🧪 Nə etdik — iki nümunə
NümunəFormatOverall result
ZəifSESSION1001 ... SESSION1100 (ardıcıl)Extremely poor — 0 bit effektiv entropiya
Güclü100 ədəd təsadüfi 32-hərfli hex (secrets.token_hex)Excellent

Ardıcıl token-də bir nümunə görən kimi növbətini dərhal tapmaq olar (+1). Təsadüfi token-də əlaqə yoxdur, təxmin mümkün deyil.

🛡️ Niyə vacib
  • Hara aid olur: sessiya cookie, password-reset token, API açarı, "unutdum" linki kimi şeylər — hamısı təsadüfi olmalıdır, yoxsa hücumçu təxmin edib başqasının sessiyasına girə bilər (session hijacking).
  • Qorunma: server tərəfdə kriptoqrafik təsadüfi generator işlət (məs. crypto.randomBytes, secrets modulu), ardıcıl ID və ya vaxt-əsaslı dəyəri token kimi istifadə etmə.
