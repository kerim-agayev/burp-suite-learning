Dərs 3. Encoding: URL, Base64, HTML

bitdi

Encoding = sarğı (bağlama köpüyü). Məlumat yolda pozulmasın deyə formasını dəyişir. Gizləmir, qorumur, hər kəs açır. Alət: Burp Decoder.

🔧 Üç sarğı
  • URL encoding: URL-də ? & = xidməti işarədir. Dəyərin içində olsalar, sarılır: boşluq → %20, & → %26, , → %2C, ? → %3F, < → %3C.
  • Base64: hər şeyi 64 “təhlükəsiz” simvola çevirir (A-Z a-z 0-9 + /, sonda çox vaxt =). Oxunmaz görünür, amma açarı yoxdur.
  • HTML encoding: &lt; = <, &gt; = >. XSS-in əsas müdafiəsidir: <script> kod yox, mətn kimi göstərilir.
🧪 Decoder-də nə etdik
  • brand_name%2Cmenu_languages%2Ctimezone → URL decode → brand_name,menu_languages,timezone
  • cay%20%26%20seker%3F → cay & seker?
  • eyJ1c2VyX2lkIjoxLCJpc19vd25lciI6dHJ1ZX0= → Base64 decode → {"user_id":1,"is_owner":true}
  • false ilə encode etdim → yalnız son hissə dəyişdi. Sonda Cg== = Enter (yeni sətir): görünməz simvollar da göndərilir!
  • dXNlcj1hZG1pbg== → user=admin

eyJ = {". eyJ ilə başlayan sətir Base64 içində JSON-dur (JWT də belədir) → aç və bax.

🛡️ Yadda saxla
  • Encoding = bağlama (hər kəs açır, dəyişir) · İmza = mum möhür (hər kəs oxuyur, dəyişsə bilinir) · Encryption = seyf (açarsız oxunmur).
  • JWT şifrələnmir, imzalanır → içinə parol/PIN qoyulmamalıdır.
  • Serverə gələn Base64-ə kor-koranə inanmaq olmaz (is_owner:false → true). İmza yoxlanmalıdır.
  • Filtr yalnız < axtarırsa, %3C ondan keçə bilər (filter bypass) → yoxlama decode-dan sonra edilməlidir.
