Dərs 7. Same-Origin Policy (SOP)

bitdi

Vebin əsas qorunması. CORS, CSRF, XSS-in hamısı bunun üstündə qurulub. Mərhələ 0-ın sonu.

🔧 Qayda

Bir saytın JavaScript-i başqa saytın məlumatını oxuya bilməz. Niyə: açıq bank.com tabınız varkən evil.com-un kodu onu oxuya bilsəydi, hesablarınızı oğurlayardı.

Origin = protokol + domen + port. Üçündən biri fərqlidirsə, ayrı sayt sayılır.

ABEyni origin?
https://shop.az/ahttps://shop.az/b✅ bəli (yol sayılmır)
https://shop.azhttp://shop.az❌ protokol fərqli
https://shop.azhttps://api.shop.az❌ domen fərqli (subdomen = ayrı)
https://shop.azhttps://shop.az:8080❌ port fərqli
🧠 Ən vacib incəlik: oxumaq ≠ göndərmək
evil.com → bank.com-a sorğu GÖNDƏRƏ bilər     ✅ (SOP mane olmur)
evil.com ← cavabı OXUYA bilməz                 ❌ (SOP dayandırır)
  • CSRF: oxuya bilmir, amma göndərə bilir → əməliyyat etdirir (“pul köçür”).
  • XSS: kod saytın öz içində işləyir = eyni origin → SOP mane olmur, hər şeyi oxuyur. XSS SOP-u keçir.
🌐 CORS: nəzarətli istisna

Sayt özü başqa origin-dən məlumat almaq istəyəndə, həmin server icazə başlığı göndərir:

Access-Control-Allow-Origin: https://client.clopos.menu   ← yalnız buna icazə
Access-Control-Allow-Origin: *                            ← hər kəsə (riskli ola bilər)

Bunu öz gözümüzlə gördük: Clopos client.clopos.menu-dan ms.clopos.com-a (fərqli origin) sorğu atırdı, ACAO başlığı icazə verirdi. kmplast.az-da isə * var idi.

Yekun: SOP oxumağı dayandırır · CORS = serverin icazəsi ilə yumşaltmaq · subdomen = ayrı origin.
